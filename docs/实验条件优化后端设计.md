# 实验条件优化后端设计

Q：我的前端是web，需要我实现的服务是一个算法，输入是一串json，输出也是一串json。我已经有了本地的算法，该怎么设计和web的接口？

A：现在需要做的就是在本地算法外面包一层 Web 外壳，让它能和前端对话。设计这个接口时，主要有三个决策点：**用什么 HTTP 方法、是同步还是异步、请求与响应的格式**。



## 整体方案

```HTTP
Web 前端
  |
  | POST /api/v1/edbo/tasks
  v
FastAPI 服务
  |
  | 1. 校验 JSON
  | 2. 转成 EDBO+ 需要的 CSV
  | 3. 后台执行 EDBOplus().run(...)
  | 4. 读取推荐结果和 pred_*.csv
  v
任务存储 / 临时文件目录 / Redis
  |
  | GET /api/v1/edbo/tasks/{task_id}
  v
返回推荐实验 + 预测信息
```



## HTTP方法

- 方法：发送 JSON 数据给服务端，标准做法是使用 POST。GET 请求的 URL 长度有限且不适合传复杂 JSON。

- 路径：推荐用名词 \+ 动作，比如 `/api/v1/algorithm/run` 或 `/api/v1/compute`。带版本号（`v1`）是很好的习惯。

- 可先实现的三个接口：

```HTTP
POST /api/v1/edbo/tasks
GET  /api/v1/edbo/tasks/{task_id}
GET  /api/v1/edbo/tasks/{task_id}/result
```

其中：

- `POST /api/v1/edbo/tasks`：提交优化任务，立即返回 `task_id`。

- `GET /api/v1/edbo/tasks/{task_id}`：查询任务状态。

- `GET /api/v1/edbo/tasks/{task_id}/result`：任务完成后获取算法结果，也可以把结果直接放在状态接口里。



## 异步接口——轮询

1. 前端 POST 提交任务，拿到 `task_id`。

2. 前端每 2 秒（或递增间隔）GET `/status/{task_id}`。

3. 后端返回 `processing` 则继续，返回 `completed`（附结果）则停止。

4. 给轮询加一个最大超时（如 60 秒），超时后提示用户失败。



提交任务 → 返回任务ID → 前端轮询结果。

- 步骤1：提交任务

```HTTP
POST /api/v1/algorithm/run
Content-Type: application/json

{ "input": { ... } }
```

返回 `202 Accepted`：

```JSON
{
  "task_id": "abc-123",
  "status": "pending",
  "status_url": "/api/v1/algorithm/status/abc-123"
}
```



- 步骤2：查询结果

前端用 `task_id` 定期轮询：

```HTTP
GET /api/v1/algorithm/status/abc-123
```

- 如果还在算，返回 `{ "status": "processing" }`

- 完成后返回 `{ "status": "completed", "data": { ... } }`

- 失败则 `{ "status": "failed", "error": "错误描述" }`

## 后端模块划分

代码结构：

```Python
app/
  main.py                 # FastAPI 入口
  api/
    edbo.py               # HTTP 路由
  schemas/
    edbo.py               # Pydantic 请求/响应模型
  services/
    edbo_service.py       # JSON <-> CSV，调用算法
    task_service.py       # 任务状态管理
  workers/
    executor.py           # 线程池 / Celery / RQ
  storage/
    local_storage.py      # 临时 CSV、结果文件管理
```

核心算法不要写在 HTTP handler 里，封装成类似：

```Python
def run_edbo_recommendation(request: EdboRequest) -> EdboResult:
    # 1. candidates -> DataFrame
    # 2. null -> "PENDING"
    # 3. 保存为 CSV
    # 4. 调用 EDBOplus().run(...)
    # 5. 读取结果 CSV / pred_*.csv
    # 6. 转成 JSON 返回
```

## 大模型建议的技术选型（这些需要确认和学习）

- Web 框架：`FastAPI`

- 参数校验：`Pydantic`

- 后台执行：开发阶段用 `ThreadPoolExecutor`

- 生产任务队列：如果并发或耗时明显，换成 `Celery + Redis` 或 `RQ + Redis`

- 临时文件：每个任务一个独立目录，例如 `workdir/{task_id}/input.csv`

- 任务状态：开发阶段可用内存字典，生产建议 Redis 或数据库

- CORS：允许前端域名访问

- 鉴权：内部系统可先用 `X-API-Key`，正式系统再考虑 JWT



## 封装本地算法

把算法逻辑抽象成一个可调用的函数或类，避免直接在 HTTP handler 里写核心代码。这样既可以独立测试，也方便以后换框架。

让大模型写了一个完整的 FastAPI 异步服务示例，实现了任务提交、后台计算和状态轮询。算法部分模拟了一个耗时的同步操作（用 `time.sleep`），并通过线程池执行以避免阻塞事件循环。

```Python
# main.py
import uuid
import time
import threading
from concurrent.futures import ThreadPoolExecutor
from enum import Enum
from typing import Dict, Any, Optional

from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
from fastapi.responses import JSONResponse

app = FastAPI()

# ---------- 状态管理（内存版，仅演示用） ----------
class TaskStatus(str, Enum):
    PENDING = "pending"
    PROCESSING = "processing"
    COMPLETED = "completed"
    FAILED = "failed"

class Task:
    def __init__(self, task_id: str):
        self.task_id = task_id
        self.status = TaskStatus.PENDING
        self.result: Optional[Dict[str, Any]] = None
        self.error: Optional[str] = None

# 用字典保存任务，生产环境应使用 Redis 或数据库
tasks: Dict[str, Task] = {}
# 线程池，用于执行同步阻塞的算法
executor = ThreadPoolExecutor(max_workers=4)

# ---------- 你的本地算法 ----------
def heavy_algorithm(input_data: dict) -> dict:
    """
    模拟耗时算法：纯同步函数，处理时间在几秒到几十秒
    """
    # 模拟计算耗时
    time.sleep(10)  # 在实际项目中替换为真正的算法
    # 返回处理结果
    return {
        "processed": True,
        "input_summary": str(input_data)[:100] + "...",
        "compute_time_sec": 10
    }

# ---------- 请求/响应模型 ----------
class RunRequest(BaseModel):
    input: Dict[str, Any]

class RunResponse(BaseModel):
    task_id: str
    status: TaskStatus
    status_url: str

class StatusResponse(BaseModel):
    task_id: str
    status: TaskStatus
    data: Optional[Dict[str, Any]] = None
    error: Optional[str] = None

# ---------- 辅助函数 ----------
def run_task_in_thread(task_id: str, input_data: dict):
    """
    在独立线程中执行算法，并更新任务状态
    """
    task = tasks.get(task_id)
    if not task:
        return
    try:
        task.status = TaskStatus.PROCESSING
        result = heavy_algorithm(input_data)
        task.result = result
        task.status = TaskStatus.COMPLETED
    except Exception as e:
        task.error = str(e)
        task.status = TaskStatus.FAILED

# ---------- API 接口 ----------
@app.post("/api/v1/algorithm/run", response_model=RunResponse, status_code=202)
async def submit_task(req: RunRequest):
    """
    提交异步算法任务，立即返回 task_id
    """
    task_id = str(uuid.uuid4())
    task = Task(task_id)
    tasks[task_id] = task

    # 提交到线程池执行（不阻塞请求）
    executor.submit(run_task_in_thread, task_id, req.input)

    return RunResponse(
        task_id=task_id,
        status=TaskStatus.PENDING,
        status_url=f"/api/v1/algorithm/status/{task_id}"
    )

@app.get("/api/v1/algorithm/status/{task_id}", response_model=StatusResponse)
async def get_task_status(task_id: str):
    """
    查询任务状态，前端可定期轮询此接口
    """
    task = tasks.get(task_id)
    if not task:
        raise HTTPException(status_code=404, detail="Task not found")

    return StatusResponse(
        task_id=task.task_id,
        status=task.status,
        data=task.result if task.status == TaskStatus.COMPLETED else None,
        error=task.error if task.status == TaskStatus.FAILED else None
    )

# ---------- 启动命令 ----------
# uvicorn main:app --host 0.0.0.0 --port 8000
```

前端轮询示例

```JavaScript
async function runAlgorithm(inputData) {
  // 1. 提交任务
  const submitRes = await fetch('/api/v1/algorithm/run', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ input: inputData })
  });
  const { task_id, status_url } = await submitRes.json();

  // 2. 轮询状态
  const maxAttempts = 60;          // 最多轮询60次
  const intervalMs = 2000;        // 每2秒查一次
  for (let i = 0; i < maxAttempts; i++) {
    const statusRes = await fetch(status_url);
    const statusData = await statusRes.json();

    if (statusData.status === 'completed') {
      return statusData.data;     // 成功，返回结果
    } else if (statusData.status === 'failed') {
      throw new Error(statusData.error || 'Task failed');
    }
    // 否则继续等待
    await new Promise(resolve => setTimeout(resolve, intervalMs));
  }
  throw new Error('Task timeout');
}

// 使用示例
runAlgorithm({ key: 'value' })
  .then(result => console.log('算法结果:', result))
  .catch(err => console.error('出错:', err));
```



## 其他细节

- 超时设置：如果是同步接口，给 HTTP 服务器和反向代理（如 Nginx）设一个合理的超时（比如 30 秒），避免卡死。

- 请求大小限制：如果前端传来的 JSON 可能很大，记得调整服务器允许的最大请求体大小。

- 跨域 \(CORS\)：前端是 Web 调用时，一定要配置 CORS，允许前端的域名访问。

- 认证：如果这个算法接口不公开，加上简单的 API Key 或 JWT 验证，放在 Header 里。

- 预热与常驻：如果算法需要加载大模型或大量数据，要在服务启动时提前加载到内存，不要每个请求都重新加载。



## 需要确认的疑惑

1. 前端传的是完整候选空间，还是只传已实验记录？
答：EDBO\+ 通常需要完整候选空间，其中未实验目标值为 `null` / `PENDING`。

2. `candidate_id` 是否由前端生成？
答：建议前端或后端都可以生成，但必须保证同一个实验条件有稳定 ID。

3. 是否需要保存历史任务？如果用户刷新页面后还要查结果，就不能只用内存任务状态，需要 Redis 或数据库。

4. 是否允许多个用户同时提交任务？如果允许，需要考虑队列、并发数限制、任务隔离和文件目录隔离。

5. 是否需要返回完整预测表？
如果候选空间很大，建议只返回推荐项，完整 `pred_*.csv` 作为文件下载或分页接口。
